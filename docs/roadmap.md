## 下一步：受控试点上线

目标是让一个组织在私有网络里真正用起来。每一项都是一个普通 PR，并附带测试。

7. **前端 UI 规整**（规范见 [design.md](design.md)，选型见 [ADR-0006](adr/0006-ant-design-ui-stack.md)）
   - 每个 PR 迁移一组页面：按 design.md 换成 antd 组件，删除这组页面不再使用的遗留样式，同步把测试中的遗留 class 选择器换成语义选择器，PR 描述附桌面和 375px 截图。
   - UI-0 基调：design.md、ADR、接入 antd、主题、App Shell、去除里程碑文案、遗留样式隔离。
   - UI-1 共享组件、术语与时区：`web/src/ui/` 下的 `PageHeader`、`StatusTag`、`ButtonLink`；生命周期中文化，界面英文术语按术语表替换。时区单独一个 PR：`formatDateTime` 和现有 `datetime-local` 输入统一按 `Asia/Shanghai`，测试在多个设备时区下得到相同的 ISO 时间。
   - UI-2 认证页：登录、修改密码。验收：401、429、安全返回路径与改密流程不退化；输入控件（含 placeholder）对比度实测达标。
   - UI-3 我的工作、通知中心。验收：任务入口、未读操作、375px 可用；在试点终端上记录首屏加载时间，明显退化时提前做路由代码分割。
   - UI-4 审查计划与审查活动：列表、创建向导、详情、团队面板。验收：同键重复提交、结果未知、关闭再打开表单都复用同一幂等键；409 按原因区分。
   - UI-5 发现项与整改项详情，包括 Scenario 适配器和证据上传。验收：观察项直接关闭、整改与验证；原始字节上传、中文文件名、413/415、授权下载。
   - UI-6 管理视图、管理进度、管理设置。验收：指标和 `as_of` 来自后端，导出与当前筛选一致，普通用户拿不到管理权限。
   - UI-7 收尾：删除剩余遗留样式与 `.ui-modern` 包裹，必要的路由代码分割，两个场景的完整用户旅程在试点终端上走通。
8. **试点上线**
   - 范围：1 个组织、2 个部门、10–20 人、10–30 个 Case，使用两个场景。
   - 上线前按一页检查清单逐项确认：版本、备份新鲜度、恢复演练结果、监控、回滚方式、停止条件。
   - 已知运维风险：main 无服务端分支保护（GitHub 套餐限制），依赖 PR + 人工合并约定。
   - 由维护者决定何时开放；运行一周后复盘。

## 之后（有真实数据再做）

- 数据保留：通知、Session、Activity 归档策略，以及证据的保留期与删除规则。Session 行删除需与审计 FK（RESTRICT）一起设计。
- 企业集成：OIDC/SSO、MFA、邮件或企业 IM 通知。
- 规模：查询性能回归、keyset 分页、负载测试。导出的 10000 行上限针对输出，不限制投影阶段的内存和时间；规模扩大前需要精简共享投影里的明细构建并做容量测试。`evidences.storage_key` 加唯一索引（也能顺带保证一个对象只对应一条 Evidence）。
- 导出的平台审计事件（`management_export`），等合规有要求时再加。
- Evidence 存储 key 认领表（登记与孤儿清理通过唯一约束互斥），根治清理竞态。
