## 下一步：受控试点上线

目标是让一个组织在私有网络里真正用起来。每一项都是一个普通 PR，并附带测试。

2. **运维基础**
   - 结构化日志，包含 request_id、路由、状态码、耗时，不记录密码、Cookie 和密钥。
   - `/health/live` 与 `/health/ready`，后者检查数据库和迁移版本。
   - 登录限流，且不能借此枚举账号。
   - Session 的 `last_seen_at` 按间隔更新，并清理过期 Session。
   - 显式配置连接池、语句超时、锁超时。
3. **创建幂等**
   - 只覆盖 ReviewPlan 和 ReviewCase 的创建，幂等键范围为 `组织 + 用户 + 操作 + 键`，并带请求指纹。
   - 同键同请求返回同一结果；同键不同请求返回 409；并发请求只创建一次。
   - 不做通用幂等框架。
4. **证据文件**
   - 服务端生成存储键，流式上传，由服务端计算 SHA-256 和大小，限制文件大小。
   - 先写对象，再用短事务写元数据和 Activity。
   - 定时清理孤儿对象。
   - 下载时重新鉴权，并设置安全响应头（`Content-Disposition: attachment`、`nosniff`）。
5. **每日自动提醒**
   - 每天 09:00（Asia/Shanghai）由外部调度调用现有的 `reminder_sweep`，并记录最近一次运行的时间、结果和计数。
6. **快照导出**
   - 管理视图导出 CSV 和 XLSX，两者来自同一份快照，上限 10,000 行，超限整体失败。
   - 防止公式注入，并正确处理中文和时区。
7. **试点上线**
   - 范围：1 个组织、2 个部门、10–20 人、10–30 个 Case，使用两个场景。
   - 上线前按一页检查清单逐项确认：版本、备份新鲜度、恢复演练结果、监控、回滚方式、停止条件。
   - 已知运维风险：main 无服务端分支保护（GitHub 套餐限制），依赖 PR + 人工合并约定。
   - 由维护者决定何时开放；运行一周后复盘。

## 之后（有真实数据再做）
