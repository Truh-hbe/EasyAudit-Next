## 下一步：先完成 UI/UX 整理，再受控试点

Pilot-1 到 Pilot-6 的代码能力已交付；真实环境部署与用户开放仍待确认。试点前按 [design.md](../design.md) 整理前端，以固定组件、图标和交互规范建立可维护的界面基线。当前规范已提出，Ant Design 及页面迁移尚未实现。

### Pilot-UI：前端设计与整理

顺序为 UI-1 → UI-2 → UI-3 → UI-4 → Pilot-7；每阶段可以拆为多个单一关注点的普通 PR，保持现有业务旅程可运行，不新增 Gate 或阶段状态文件。

| 里程碑 | 交付内容 | 完成依据 | 估算工作量 |
|---|---|---|---|
| UI-1 基础接入 | 精确锁定 `antd@6.6.5`、`@ant-design/icons@6.3.4`；主题/中文 locale/反馈上下文；侧栏与移动导航；语义组件样例 | typecheck、lint、单测、build 与导航浏览器旅程通过；核实实际试点浏览器版本和组件兼容；记录构建体积 | 2–3 开发日 |
| UI-2 列表与入口 | 登录改密、工作台、活动集合、通知、管理视图与导出；统一状态、名称、空/加载/失败；仅使用现有筛选 | 相关浏览器旅程与筛选/分页/导出行为通过；关键视口和键盘操作 review；授权范围不扩大 | 3–4 开发日 |
| UI-3 详情与协作 | Plan/Case 创建、Case/Finding/Action 详情和管理设置；拆分长页面；统一团队/参与人/证据/提交与验证；删除已迁移的重复 CSS | 创建幂等、生命周期命令、上传下载、驳回原因与权限失败回归通过；两个场景保持精确版本解释 | 5–7 开发日 |
| UI-4 试点前验证 | 清理旧样式补丁；两个场景完整用户旅程、实际终端、响应式、200% 缩放与可访问性复核；同步使用文档 | 既有 CI 全绿，真实后端旅程与代表性用户操作验证完成；阻断核心流程的缺陷已修复，剩余问题记录在 PR/Issue | 2–3 开发日 |

以上为单名熟悉项目的实现者、既有 API 无重大变更时的估算，总计约 12–17 个开发日；不包含 review 等待、终端升级和新读侧接口工作量。UI-1 完成后按实测情况重估日历安排，不承诺固定上线日期。组件依赖接入和各页迁移分别 review，不能把设计文件完成等同于 UI 已完成。

优先处理影响核心流程与正确性的事项：请求/上传协议、创建幂等键、授权与冲突反馈、主操作可发现性、键盘表单和窄屏布局。暗色主题、自定义图表、动画、全局计划/发现/任务列表等扩展放在试点反馈之后。名称选择或新筛选缺少授权接口时，另开读侧设计 PR 并重新估算，不在前端模拟完整数据。

### Pilot-7：受控试点上线

目标是让一个组织在私有网络里真正用起来。UI-4 完成后准备真实环境，依据 [deploy/README.md](../deploy/README.md) 确认版本、备份新鲜度、恢复演练、监控、回滚方式与停止条件，开放真实用户由维护者当次决定。

- 范围：1 个组织、2 个部门、10–20 人、10–30 个 Case，使用两个场景。
- 上线前在实际终端演练登录、创建、整改/证据、验证、通知和导出；运维 smoke 与恢复验证使用该环境的配置。
- 已知运维风险：main 无服务端分支保护（GitHub 套餐限制），依赖 PR + 人工合并约定；其他已接受边界见 architecture 与部署说明。
- 运行一周后复盘任务完成情况、卡点、失败操作与用户反馈，形成修复优先级，再决定是否扩大范围。

## 之后（有真实数据再做）

- 数据保留：通知、Session、Activity 归档策略，以及证据的保留期与删除规则。Session 行删除需与审计 FK（RESTRICT）一起设计。
- 企业集成：OIDC/SSO、MFA、邮件或企业 IM 通知。
- 规模：查询性能回归、keyset 分页、负载测试。导出的 10000 行上限针对输出，不限制投影阶段的内存和时间；规模扩大前需要精简共享投影里的明细构建并做容量测试。`evidences.storage_key` 加唯一索引（也能顺带保证一个对象只对应一条 Evidence）。
- 导出的平台审计事件（`management_export`），等合规有要求时再加。
- Evidence 存储 key 认领表（登记与孤儿清理通过唯一约束互斥），根治清理竞态。
