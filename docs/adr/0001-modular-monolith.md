# ADR-0001：以模块化单体作为起始架构

- 状态：Accepted
- 日期：2026-08-21

## 决策

EasyAudit-Next 从模块化单体开始。Platform、Review Core、Management Views 与 Scenarios 使用清晰模块边界，但共享一次部署和同一事务边界。核心领域包不依赖 Web 框架、ORM 或数据库。

## 理由

项目当前最大的风险是领域边界错误，而非单机吞吐量。模块化单体可以保留重构速度、事务一致性和低运维成本，同时通过依赖规则为未来拆分留下空间。

## 后果

- 不在 M0 引入微服务、事件总线或分布式事务。
- 模块间通过显式应用服务和领域契约交互。
- 当团队、部署或扩展压力出现可验证证据后，才讨论服务拆分。
